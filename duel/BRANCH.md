# 分支：技能小人对战 (duel)

> 2026-10-09 定稿；选型已回填（2026-10-09 调研报告，关键工具均经 npm/GitHub API 实测核实）

## 一句话
战斗模拟引擎驱动的 2.5D 擂台棋盘自动对战，全自动产出 30~60s 竖屏成片。

## 已定
- 战斗机制：**实时自动混战**（自动棋式：棋子自主走位/普攻/放技能，无玩家输入）
- 画面：2D / 2.5D，**擂台棋盘视角**——人物如棋子在擂台上互殴
- 对战结构：单场决胜负，30~60s
- 驱动：战斗模拟引擎（血量/伤害/技能由代码逻辑决定，随机种子可复现）
- 解说：MVP 用「字幕 + 音效」零配音
- 角色形象：自创（吸血鬼 vs 狂战士风格）

## 选型（2026-10-09 回填）
- [x] 模拟引擎：**自写 TS 确定性核心**——固定 tick(20~60Hz) + 固定随机种子 + 阵容配置为唯一输入，
      过程写 JSONL 事件日志 `{tick, type: attack/damage/knockback/death/cast, from, to, value, x, y}`。
      词汇表抄 [Pokemon Showdown SIM-PROTOCOL](https://github.com/smogon/pokemon-showdown/blob/master/sim/SIM-PROTOCOL.md)，回放心智模型参考 OpenRA「种子+指令日志重演」
- [x] 走位 AI：Reynolds steering 三件套（seek 接敌 / arrive 攻击距离内停 / flee 拉开），开放擂台无需 A*，
      参数抄 [GDQuest godot-steering-ai-framework](https://github.com/GDQuest/godot-steering-ai-framework) demos
- [x] 渲染栈：**PixiJS 8 无头逐帧 + ffmpeg 合成**（实测 8.22.0 / 2026-10-01 发布 / MIT / 当日仍在提交，
      [npm](https://www.npmjs.com/package/pixi.js)）。
      备选：[Remotion 4](https://github.com/remotion-dev/remotion)（4.0.534，个人及≤3人公司免费可商用）/
      [Godot 4.7](https://github.com/godotengine/godot) headless `--write-movie`。
      排除 Motion Canvas：npm 末版 3.17.2 停在 2024-12，近两年未发版
- [x] 角色管线：**程序化矢量小人（角色=代码参数）**——零美术成本、新角色趋近零成本、模拟器直接读写角色状态。
      打击感（伤害数字/震屏/hit-stop/光效）全挂渲染层事件钩子，与角色风格无关。
      升级路径：像素风（Kenney CC0 占位跑通 → PixelLab AI 出原创，Aseprite $19.99 买断 + 无头 CLI 批量导出）
- [x] 技能系统 MVP 深度：每角色 普攻 + 1 主动技 + 1 被动（2026-10-09 拍板），全部走事件日志
- [x] 技能数值风格：**纯数值技能**（每技固定伤害/回血数值，稳定可控；不用随机浮动）
- [x] 被动呈现：**开场亮明**——VS 卡直接写明被动，观众带预期看战局，触发时字幕提示

## 包装与节奏（2026-10-09 第二轮拍板）
- [x] 胜负判定：**纯血量归零**。保险丝：战斗超 45s 双方伤害递增强制收尾（防拖场，不改判定逻辑）
- [x] VS 卡：**大字报冲击式**（撞入动画+大字+音效；系列感后期用战绩角标补）
- [x] VS 卡时机：MVP 实现「开场即卡」，同时实现「先打后卡」为可切换参数（--cold-open），
      小样 A/B 两版发朋友看反馈，哪个好用哪个
- [x] 首期角色：**吸血鬼 vs 狂战士**（吸血=残血反杀反转点；狂暴=血少攻速快自动推向高潮；
      配色深红暗紫 vs 橙铁灰）
- [x] 音效：**jsfxr 程序化生成**（渲染时按事件类型现生成，零素材管理零版权）；
      违和则退 Kenney CC0 打击音效包
- [x] 结算画面：**胜者亮 + 评论区点播引导**（「你想看谁打谁？评论区点播」）——接住阵容点播模式
- [x] 标题模板：等系列名候选出炉一起定（生成中）
- [x] 开发方式：AI 全程代写，用户拍板 + 验收成片（2026-10-09 确认）
- [x] 擂台场景：**棋盘格擂台 + 顶/底信息条**（2026-10-09 拍板）——棋盘格地面紧扣「棋子打架」设定；
      顶部放双方名字+血条，底部放技能状态/伤害统计/点播引导字幕
- [x] 镜头语言：**固定机位 + 重击推拉**（重击瞬间轻微推拉+震屏；基础仍是固定镜头，
      模拟器坐标直接映射屏幕）

## MVP 验收标准
一条全自动链路：`配置双方 → 跑模拟 → 渲染成片`，产出 1 条能看的 30~60s 对战视频，中间不进剪辑软件。

## 风险
- 「成片好看」无基准（参考视频仍缺）→ 矢量小人画质上限偏低，对冲=特效层拉满；参考视频到位后校准
- 本机缺口（实测）：ffmpeg 未安装 → 首周 `brew install ffmpeg`

## 实现记录（2026-10-10 初版代码完成）
- [x] **渲染栈变更**：PixiJS 无头渲染需要原生 canvas 依赖（安装被环境拦截），实际实现为
      **纯 TS 软件光栅器**（shared/render/framebuf.ts RGBA 帧缓冲 + 字形图集贴字）
      → ffmpeg rawvideo 管道直编 h264。零 npm 依赖、零编译、可复现，MVP 更稳。
      后续需要复杂光效时再评估引入 PixiJS/sharp
- [x] 中文渲染：Pillow 预渲染字形图集（STHeiti Heiti SC，744 字形，动态扩字符集脚本 shared/tools/）
- [x] 模拟器：60Hz 固定 tick + mulberry32 确定种子 → JSONL 事件日志（damage 带 crit/x/y）
- [x] 平衡性（参数扫描 12 种子）：夜伯爵 攻速0.85/吸血45% vs 断岳 攻26/血950 → 胜率 6/12，时长 26~29s
- [x] 机制：暴击 15% ×1.8、闪避 10%（evasive）、狂暴攻速叠加、45s 加时保险丝
- [x] 音频：程序化 BGM（140bpm 小调四轨）+ jsfxr 音效（punch/crit/skill/death/vs-slam）混音
- [x] 一键：`node duel/run.ts [seed] [--cold-open]`
- 样片：out/duel/duel_77.mp4（30.8s，B 胜）、out/duel/sample_final.mp4（31.5s）
- 已知短板（下轮迭代）：无重击推拉镜头；死亡演出简单；血条无缓动；BGM 单曲循环略单调

## 交手机制修订（2026-10-10）
- [x] **移除普通攻击**：英雄不再有普攻数值或普攻事件。
- [x] **接触触发技能**：双方接近到 `contactRange` 后直接释放主动技能；技能冷却期间重新寻路但不攻击。
- [x] **技能后重新寻路**：技能命中后受击方和施法方同时被弹开，进入恢复期；恢复期结束后再次计算路径接近。
- [x] **被动改为技能效果**：吸血 = 技能伤害后的回血效果；狂暴 = 每次技能命中后蓄力，下一次技能伤害提升；画面表现为技能横幅/光效/结果，不再单独做暴击普攻 proc。
- [x] **样片验证**：`out/duel/duel_42.mp4`；事件日志验证普通攻击事件为 0，技能事件 15，技能效果事件 15。
